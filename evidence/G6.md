# G6: replay viewer, deploy, the stop rule

*2026-10-05. Commands are given with each fact.*

## A replay file loads and plays back in the client

- Screen `#/replays` (nav: Replays): choose a file or paste its text. `store.viewReplay` (client/store.js) refuses with the key and the reason: not JSON, wrong format, wrong version, a missing key,
  a kind other than delve or floor, an unknown realm, hero class or monster, a party that is not 1 to 4 heroes, an event log that is not lists, an event log that does not play (a dry run of the pure reducer).
  Otherwise it runs `verifyReplay` (hash, content version, a fresh simulation) and shows the Battle screen with the verdict on top. A changed file shows "Not verified: hash mismatch" and still plays from its own numbers;
  a file from other content shows "content mismatch" and plays too. Watching a replay never changes the save.
- Tests: `node --test tests/unit/client-store.test.mjs` (3 viewer tests, 6 mutations of the store each killed once the plan check test was added) and
  `node --test tests/browser/client.test.mjs` (a delve file and a legend fight with its phases through the real page, a damaged file, a file from other content, the save compared before and after).

## CI proves tests, determinism, budgets and the deploy

- `.github/workflows/ci.yml` (push and pull request): `npm ci`, `npm test` (583 tests: unit, the determinism suite with the static scan of `sim/`, golden hashes, the headless-browser tests, the budget tests),
  `node checks/measure-client.mjs` (budgets, printed), a build of the deployable page (`node tools/bundle.mjs`, which refuses invalid content), and the three balance runners (`checks/balance.mjs`,
  `checks/balance-expedition.mjs`, `checks/balance-legends.mjs`; each exits non-zero when a bound fails).
- `.github/workflows/pages.yml` (push to main or this branch): builds `dist/` and deploys it to GitHub Pages.
