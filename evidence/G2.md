## 2. Does the cross-check actually bite? (mutation experiment)

`node checks/mutate-content.mjs` (output in `evidence/G2-mutation.txt`; about four minutes). It changes **each of the 1,747 leaf
values** of the content files one at a time, in scratch copies, and runs the schema, cross-reference and DESIGN.md comparison
tests. A **survivor** is a content value that nothing pins to the design.

- First run: 1,747 mutated, **56 survivors**: 23 display names of monster, special and basic skills (the design lists those
  skills by id and never names them), 30 hero first names, and the 3 element names in the runbook's `argTypes`.
- Two rules were worth pinning, so two tests were added: monster/special/basic skill names are the title-cased id, and the
  runbook's element values are exactly the realms' elements. Both were then shown to fail on a planted change.
- Final run: **1,747 mutated, 30 survivors**, all of them the hero first names in `names.json` (10 per realm). Those are
  flavour text the design does not define; they are constrained only by the schema (strings, distinct, at least 5 per realm).
  That is an accepted gap, recorded here so it is a decision and not an oversight.

## 3. What the evaluation caught that reading would not

- **A loose schema.** The sweeps showed the runbook's `argTypes` accepted any object and any text in `values`; both tightened.
- **Five of my own test mistakes**, each raised as "is this the test or the content?" and each traced to the test:
  two design sentences are line-wrapped mid-phrase; the actions table has a parenthetical in its arguments cell; a regex missed a
  double closing parenthesis; I expected the realm element on utility skills that deal no damage. None was a content error: **the content matched the design in every
  table on the first complete run**, which is what generating it from the design's tables should give, and the test now
  guarantees it stays so.
- **A threshold of my own** (I guessed 800 integers; there are 594) failed a sweep's sanity check. Corrected to the real count.
- **A test that could never fail**: I wrote `assert.equal(...) && assert.match(...)`, whose second half never ran (`assert.equal`
  returns `undefined`). Found on review and rewritten as two statements.
- The validator itself was mutation-checked: 7 mutations (maximum, minimum, unknown keys, required keys, enum, the whole
  cross-reference stage, one reference rule) all turn the suite red.

## 4. Notes

- **Files:** `sim/schema.js` 75 lines, `sim/contentcheck.js` 149 lines; both were added to the static scan's reviewed
  allowlist for `Object.keys` (they walk external JSON and only report errors; their key order never reaches a simulation).
- **Test-only hook:** `CONTENT_DIR` in `tests/helpers/content.mjs` points the suite at a scratch copy of `content/` for the
  mutation experiment. It is not set in normal runs.
- **The generators** that wrote `content/*.json` and the schemas from the design's tables were one-off scripts and are not in
  the repository; the permanent guarantee is the tests above, not the generator.
- **Not in G2:** the content bundle for `file://` (the client cannot `fetch` local JSON) belongs to G4; the browser loads
  content as text through the same `loadContent`, which already takes texts and not file paths.
