# Evidence: G1 (the deterministic core)

*2026-10-01. Gate: `sim/` with no DOM and no browser dependency (PRNG, combat resolver, encounter and delve runners,
replay writer and reader), byte-identical replays over 1,000 seeds, a test that fails loudly on a random or clock read,
replay hashes equal between Node and the browser, a replay round trip.*

Everything below was produced by a command run in this session. `npm test` (= `node --test "tests/**/*.test.mjs"`)
ran 203 tests: **203 pass, 0 fail, 0 skipped**, about 3 seconds, three clean consecutive runs.

## 2. Injection experiments (does the guard actually fire?)

Each fault was planted in `sim/`, the whole suite run, and the file restored (the suite is green again after each).

| Planted in the sim | Tests that failed |
|---|---|
| `Math.random()` in the hit path, value-neutral | static scan (combat.js), traps |
| `Date.now()` in the hit path, value-neutral | static scan, traps |
| `Math.random()` that changes outcomes | static scan, 1,000-seed determinism, golden, traps, fuzz replay (5 tests) |
| `globalThis` counter, value-neutral | static scan |
| module-level counter that changes which monsters appear on every other call | 1,000-seed determinism, input-key-order, golden, delve same-seed, replay round trips (3 of them), tamper-by-re-simulation (8 tests) |

My first version of the last experiment changed an unused variable and so showed no failures; it was a no-op, caught
because "no failures" was not what the earlier ones had looked like. It was redone on a variable that matters.

## 3. The browser check, and what it does not show

`HeadlessChrome/141` (from the preinstalled Chromium) ran the 30 golden inputs: **all 30 replay hashes equal Node's and
the committed ones**, as do the content hash, `sha256("abc")` and the canonical-JSON vectors. The `sim/` modules loaded
from a plain static server with no bundler.

**Caveat.** Chromium and Node are both V8, and this environment has no Firefox. The check shows the core runs unchanged
as browser modules with no Node globals; it does not by itself show independence from V8. That rests on the integer-only
arithmetic (enforced by the scan: no floating-point `Math` functions, no `/` outside `arith.js`, no decimal literals), on
the published SHA-256 vectors, and on the replay format carrying no floats. SPEC.md requires current Firefox as well, so
**G6's CI should run this same test in Firefox**.

## 7. What the evaluation caught that reading would not (details in LOG.md R2 to R8)

- A **content bug**: the generator flagged `curse` with a realm rider because it matched the phrase "realm rider" inside
  "(no realm rider)". Counts were all correct; a behavioural test caught it. All 12 flags were then audited against DESIGN.
- A **silent data loss**: the first generator pass dropped every signature monster's special skill (backticks in the
  table); a spot-check of one monster found it.
- A **code gap**: units accepted an impossible starting HP; now refused.
- A **validator defect**: after one refusal it added a second, bogus one; now one reason per fault.
- **Surviving mutations**: 4 of the 12 mutations tried in R4 to R6 survived the first test set (crit boundary, draw
  arguments, back-row placement, resting the downed); each got a test that kills it.

## 8. Notes for later gates

- **Gear cliff (for G3).** With monster skills, statuses and affixes now in the sim, a level-50 party with no gear wins 1
  of 60 level-20 delves and the same party in plain item-level-20 gear wins 60 of 60. This probe is not a balance result,
  and the no-gear case is not a state a player reaches; G3 must look at the progression from Plain to Fine to Runed and the
  upgrade stars, in line with the approved intent (DESIGN 0.2) that gear becomes progressively more necessary.
- **Design clarifications logged** during G1: DESIGN 0.2.1 and 0.2.2 (no number changed).
- **Dev dependency added:** `playwright-core@1.56.1`, for the browser test only, used with the preinstalled Chromium (no
  download); pinned to the version matching that browser build. No runtime dependencies.
- **Not done in G1, by design:** content schemas and the table cross-check (G2), expedition code (G5), the client (G4).
